基线：nianshou1999/LibreTV `091a323e4b3082408481306b285b37c5b71b24ff`。

## 已核对的证据

- 上游 https://github.com/LibreSpark/LibreTV/issues/937 在本次查询时仍开放。报告者称 v2.16.12 / v2.19.1 在 iPhone Safari、Chrome 下复现，并称修改隐藏阈值后可用。这些是报告者的结果，本次未在 iPhone 上复现。
- package.json 为 2.16.12，依赖范围 `artplayer ^5.2.3`；package-lock.json 锁定 **5.4.0**。检查对象为 npm ci 安装的 5.4.0 发布包 `dist/artplayer.mjs`。
- Control 构造时捕获 `art.constructor`，在 `video:timeupdate` 中，当播放中、控制栏显示、设置关闭、无 hover 和输入焦点、超过 3000ms 时隐藏。设置面板打开本来就有保护，不能将所有菜单问题都归因于缺少该保护。
- 移动端视频 click 单独触发 controls.toggle；按钮点击和进度触摸不依赖该阈值。进度条 `.art-progress` 和 `.art-controls` 同属于 `.art-bottom`，原有长按排除选择器漏掉进度条。

## 补丁选择

移动端使用 MobileArtplayer 子类，仅覆盖其自身静态 CONTROL_HIDE_TIME 为 Infinity。它是时间差比较阈值，没有传入 setTimeout，因而不存在超大延时溢出的问题。普通 Artplayer 的阈值仍为 3000，不需要全局修改、引用计数或卸载恢复。使用 Artplayer.utils.isMobile，与依赖本身的交互模式一致（包括桌面 UA 的触屏 iPad 检测），避免给使用桌面交互模式的普通触屏笔记本改变行为。

保留原生视频单击切换；未增加拦截点击或强制重新显示控制栏的监听器。长按排除范围改为 `.art-bottom, .art-settings`，并清理卸载时尚未触发的长按定时器。其它字幕、HLS、预取、换集、续播、恢复和状态管理逻辑不变；未合入 PR #939 的界面改动。
